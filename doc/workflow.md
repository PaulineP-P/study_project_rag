# Workflow: процесс работы по итерациям

## Цикл одной итерации

```
1. Прочитать задачи итерации в doc/tasklist.md
        ↓
2. Убедиться что предыдущая итерация закрыта (тесты зелёные, коммит сделан)
        ↓
3. Реализовать задачи итерации
        ↓
4. Запустить проверку (команды из tasklist.md)
        ↓
5. Обновить tasklist.md (отметить выполненные задачи)
        ↓
6. Сделать коммит и перейти к следующей итерации
```

---

## Что делать до кода

1. **Прочитать** задачи итерации в `doc/tasklist.md` полностью
2. **Убедиться** что цель итерации понятна — что именно должно работать на выходе
3. **Проверить** что предыдущая итерация завершена:
   - все чекбоксы отмечены
   - `uv run pytest` проходит без ошибок
   - коммит сделан
4. **Не начинать** следующую итерацию если текущая не закрыта

---

## Как выполнять проверку

Каждая итерация имеет явную команду проверки в `doc/tasklist.md`.

```bash
# Общая проверка тестов — запускать после каждой итерации
uv run pytest -v

# Проверка конкретного модуля
uv run pytest tests/test_chunker.py -v

# Проверка запуска UI
uv run streamlit run app/main.py
```

Проверка считается пройденной если:
- команда завершается без ошибок
- все тесты зелёные
- результат соответствует ожидаемому из tasklist

---

## Когда обновлять tasklist.md

- **Сразу после выполнения каждой задачи** — отмечать чекбокс `[x]`
- **После прохождения проверки** — обновить статус итерации в таблице прогресса:
  - `⬜` → `🔄` (в процессе)
  - `🔄` → `✅` (завершена)
- **Не отмечать задачу выполненной** если проверка не прошла

---

## Правила коммита и перехода дальше

**Формат сообщения коммита:**
```
iter(N): краткое описание что сделано

Примеры:
iter(0): инициализация структуры проекта
iter(1): добавить чанкинг по страницам
iter(2): построить векторный индекс на ChromaDB
iter(6): все 5 тестов зелёные
```

**Правила:**
- Один коммит закрывает одну итерацию (или одну логическую задачу внутри итерации)
- Коммитить только когда тесты зелёные
- Не коммитить файлы из `data/`, `index/`, `.env`
- Переходить к следующей итерации только после коммита текущей

## Запрещённые действия

- ❌ Коммитить с красными тестами
- ❌ Пропускать итерации — каждая строится на предыдущей
- ❌ Коммитить `data/`, `index/`, `.env` (секреты и большие файлы)
- ❌ Устанавливать зависимости через `pip install` — только `uv add`
- ❌ Редактировать индекс вручную — только через `build_index.py`
- ❌ Генерировать ответы из общих знаний модели — только по контексту документов
- ❌ Отмечать задачу выполненной без прохождения проверки
