# Conventions: правила разработки и проверки

## Границы изменений (KISS, минимальный diff)

- Одна итерация — одна задача. Не расширять scope без явной необходимости
- Предпочитать простое решение сложному: если задача решается 10 строками — не писать 50
- Не добавлять зависимости без причины: каждая новая библиотека должна быть обоснована
- Коммит описывает одно логическое изменение, сообщение в формате:
  `feat: добавить чанкинг по страницам` / `fix: исправить пустые чанки` / `test: добавить тест на отказ`

## Архитектура модулей

```
project/
├── data/           # исходные .txt файлы (не коммитятся, только .gitkeep)
├── index/          # ChromaDB индекс (не коммитится)
├── scripts/
│   └── build_index.py   # ingest → chunk → embed → index
├── app/
│   └── main.py          # Streamlit UI + retrieval + генерация ответа
├── rag/
│   ├── chunker.py        # логика чанкинга
│   ├── indexer.py        # работа с ChromaDB
│   ├── retriever.py      # поиск top-k чанков
│   └── generator.py      # вызов LLM через OpenRouter
├── tests/
│   └── test_*.py         # тесты
├── doc/                  # документация проекта
├── .env.example          # пример переменных окружения (без секретов)
└── pyproject.toml        # зависимости через uv
```

Каждый модуль отвечает ровно за один слой пайплайна. Импорты только вниз по
стеку: `app` → `rag` → никаких обратных зависимостей.

## Правила ответа RAG

- Модель отвечает **только** на основе переданных чанков контекста
- System-промпт явно запрещает использование общих знаний модели
- Если ни один чанк не содержит ответа — система возвращает явный отказ:
  `"В загруженных документах ответ на этот вопрос не найден"`
- Каждый ответ содержит источник: имя файла (регион) и номер страницы
- Модель не додумывает и не интерпретирует сверх того, что написано в документе

## Тестовые требования

- Минимум **5 тестов** для оценки «хорошо»
- Обязательные тесты:
  - чанкер корректно разбивает документ по страницам
  - чанкер не создаёт пустых чанков
  - retriever возвращает непустой результат на релевантный запрос
  - система даёт правильный ответ на минимум 3 фактических вопроса
  - система корректно отказывает на вопрос вне тематики документов
- Тесты запускаются командой `uv run pytest` без дополнительных аргументов
- Все тесты должны быть зелёными перед сдачей (PR не принимается с красными тестами)
- Тестовые данные — отдельная маленькая фикстура, не весь датасет

## Правила по данным

- Исходные `.txt` файлы лежат в `data/` и **не коммитятся** в репозиторий
- В `.gitignore` добавить: `data/`, `index/`, `.env`
- Файл `.env.example` коммитится с заглушкой: `OPENROUTER_API_KEY=your_key_here`
- Индекс пересобирается скриптом `build_index.py` — не редактируется вручную

## Правила по зависимостям

- Все зависимости фиксируются в `pyproject.toml` и управляются через `uv`
- Версии зависимостей пинятся (`chromadb>=0.4`, а не просто `chromadb`)
- Не использовать `pip install` напрямую — только `uv add`
